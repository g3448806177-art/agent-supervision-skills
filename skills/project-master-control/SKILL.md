# 项目主控

## 识别角色与范围

主控为 `orchestrator`。已带项目登记的 `executor` / `supervisor` 按原卡履职，不重新作为根主控或另建监督链；执行者扩展须经原根主控具体批准。登记缺失先核对原计划。

按整个进行中的目标判断：多个独立工作包、跨模块依赖或复杂实施验收进入下述流程；单个问题、局部修复、简短分析和小文档直接完成。不能只按字数、文件数或专业角色分类。继续、追问和修复沿用原目标及监督；小任务扩大时保留成果，在新增实施前补齐流程，不主动启动历史项目。

安装技能不授予创建对话、选择模型、发信或费用使用权限。沿用当前用户已有授权，额外范围、预算或权限才询问；具体边界见[授权与能力](references/master-control-rules.md#授权与能力)。

## 大任务流程

1. **读取。** 全文读取本文件、[完整协作规则](references/master-control-rules.md)和[监督技能](../task-supervisor/SKILL.md)，截断补齐；记录资源、版本与读取状态，未读全先解决。
2. **事前规划。** 盘点并核对可复用成果，按规则写齐全部初始任务卡、共享接口和文件归属，包括独立监督/验收卡。保存 `MASTER_PLAN.md` 或更新同用途计划，展示链接或简表；无文件工具时在对话中完整写卡。此步骤完成前仅做必要的只读盘点和规划，不实施或分派。
3. **监督对齐。** 查登记及真实对话，实际建立或复用当前目标唯一的侧栏独立监督对话，传入原始目标、授权、计划与必要材料。监督检查目标、粒度、执行可行性和验收条件；未通过则主控修计划，由同一监督复核，通过后才能实施。
4. **按卡执行。** 实际创建普通独立执行对话，按依赖解除条件、关键路径和资源调度。主控在开工、目标变化、阶段结果或失败、修复后及交付前，有界读取执行/监督报告并协调。授权内的计划和修复由主控处理，不逐卡转给用户审批。
5. **调整与复验。** 新决定记录原话、适用范围、替代规则和受影响任务并同步；范围扩大或反复返工先[复审边界](references/master-control-rules.md#工作包粒度与返工复审)。新包先补卡并由原监督对齐；执行者可走[批准扩展流程](references/master-control-rules.md#经主控批准的执行扩展)。原卡内缺陷交原负责人修复自测，同一监督复验关闭。
6. **验收交付。** 同一监督依据最终产物、版本和必要的实际运行独立验收，执行者总结仅用于定位证据。主控更新计划及登记，报告实际完成范围、证据和未关闭问题；关键问题未关闭不报全部完成，不降低标准换取通过。缺独立验收能力时只报告实际自查。

主控维护计划，监督维护 `SUPERVISION.md`，执行者按卡实施。内部子代理、CLI 进程和提示词不能替代或冒称普通独立对话；缺工具时按完整规则处理能力缺口。

仅当用户明确只要执行提示词时，按[任务提示词](references/task-prompts.md)交付，不启动实施。
