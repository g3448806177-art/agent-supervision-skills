# 主控协作规则

规则版本：2026-11-14.5。开工顺序以[主控入口](../SKILL.md#大任务流程)为准；本文件集中定义任务卡、拆分、调度、扩展和登记约定。

## 授权与能力

- 遵守宿主系统、开发者指令和适用项目约束。创建普通对话、选模型、读取进度及跨对话发信分别受当前用户授权与工具能力限制；安装、委派或协调消息不产生额外授权。授权内不重复审批，超目标、费用或权限回用户，沉默不算批准。
- 主控批准是已有授权内的任务分派，不能替代用户授权或独立监督。批准开串不自动授权发信；无发信权限时把报告写到约定位置或本对话，由主控读取并转交。
- 分别检查创建、读取、发送、有界等待、设置和核实模型的能力。缺能力说明具体影响，继续可做的盘点、任务卡及交接；不能以内部代理替代普通对话，不能把自查称为独立验收。
- 对外写入、部署、删除及凭证操作遵守本项目有效授权，不因分派或验收扩大权限；不将凭证写入任务卡、报告或公开交付，不绕过权限或验证码。
- 隐式调用仅是指令入口，不保证宿主每次触发。当前轮结束后不承诺后台常驻；恢复时从计划和检查点续接。

## 任务卡

全部初始卡须在实施或分派前齐备，新增工作包先补卡。共用接口及共享文件负责人先确定；不能事后补卡冒充事前规划。

| 字段 | 必须说明 |
| --- | --- |
| 标识与目标 | 任务 ID、所属项目、要解决的问题 |
| 结果与范围 | 独立可验收交付物、包含及排除范围 |
| 粒度依据 | 主要不确定性、候选拆分、拆/合理由及停止拆分依据 |
| 输入 | 必要材料、路径与读取范围；复用成果的对象、版本、时效和适用口径 |
| 归属 | 负责人、输出文件、共享接口和文件写权、集成顺序 |
| 配置 | 难度、具体模型/推理强度及理由，创建后的实际配置证据 |
| 上下文 | 完整执行预算、容量和占用证据或未知、检查点及交接条件 |
| 依赖与调度 | 消费产物、最低可用状态、解除条件、工作量/时长区间及依据、关键路径和实际资源 |
| 验收 | 可检验条件、验证对象及方法；独立监督/最终验收也须有卡 |
| 约束与授权 | 禁止改动、共享约定、费用/重试预算、外部动作及已授权和待授权范围 |

## 工作包粒度与返工复审

- **按结果拆分。** 专业角色不等于工作包，一个最终交付物也可能包含多个独立结果。共享约定确定后能独立实施和验收的结果应拆卡；强耦合确需合并时记录具体依赖及阶段验收。共用一个文件时先评估抽离公共部分；“负责人熟悉”“保持风格”、文件少或上下文装得下不能单独支持合并。
- **停止拆分要有理由。** 当前包的结果完整、边界清楚、实施验证负担可控，且继续拆分不能形成有用的独立结果，或启动、重复读取、交接与集成成本预计超过收益时，可保留当前粒度。负担明显不均或仍含多个独立复杂判断时继续评估，不按镜头、文件或数量等分，不为凑对话数碎拆。
- **返工先复审。** 用户指出拆分不足、范围扩大、同类缺陷复发、持续退回或上下文负担上升时，在下一轮受影响实施前记录触发证据，区分标准/参考不清、证据不足、实现缺陷和任务过宽，再选择澄清、早期校样、局部修复、重拆或交接，由原监督复核。
- **保留成果并调整边界。** 原负责人修复只覆盖原卡内缺陷，新增独立工作不无限追加旧卡。重拆时更新卡、文件归属和集成顺序；沿用原项目、根主控与唯一监督，不要求固定旧执行对话。

## 上下文预算与并行调度

- **预算覆盖全过程。** 计入材料/读取范围、继承历史和规则、工具输出及图像、实现、自测、交接、未决问题和返修余量。记录上下文容量、当前占用、数值来源及估算方法；有可靠计数器时用 token 估计，文件/行数/字节不能直接证明容量足够。未知就标未知，以受控小包和早期检查点推进，不保证单次上下文必成。
- **执行中复核。** 初步盘点后，以及材料/工具输出超出估计时重新评估。预计容不下剩余实施与验证时，提前减少非必要输入、缩小工作包或交接。交接包含已完成证据、版本、剩余工作、接口、授权、未解决问题和下一步；材料用路径引用，不复制整段聊天。
- **按解除条件推进。** 每条依赖区分阻塞实施、仅阻塞集成和非阻塞参考。接口、类型或隔离测试替身已足够时可推进获授权的独立部分；替身不等于真实集成通过。不默认等共享模块全部完成或整批交付，共享入口负责人集成已就绪结果。
- **按瓶颈调度。** 在计划记录依赖图、工作量/时长区间及依据、关键路径、实际对话/模型额度和相关 CPU、内存、渲染并发、共享文件写权。未知资源明确未知，不把内部代理上限当普通对话上限。优先安排解除瓶颈的就绪包，其余在资源和授权内并行；比较节省的等待与启动、重复读取、交接、冲突和集成成本。
- **用实际记录校正。** 在阶段记录中保留必要的开始/结束、等待原因、返工、交接和可观测上下文用量，更新预算与排程。估计、模型名称或“全部并行”不能证明最快；只有可比运行证据可支持耗时收益结论，不为证明最优擅自重跑完整任务或增加费用。

## 经主控批准的执行扩展

前提：当前用户已允许执行者经原根主控同意创建新增普通执行对话。普通委派不等于该授权；根主控批准不扩大用户授权。

1. **执行者提案。** 保留成果，报告实际范围与原卡差异，提出新增包、归属、依赖、上下文/并行预算、模型及验收。按已有发信授权提交或写入可读取报告；等待时仅继续不受影响的原卡工作。
2. **原根主控批准。** `root_thread_id` 对应主控更新 `MASTER_PLAN.md` 和新卡，记录批准来源、本批卡 ID、允许创建者、范围、数量或明确名单、模型/预算及协调边界。超用户目标、费用或权限的部分回用户。原唯一监督对齐受影响范围后才可创建和实施；模糊同意不能代替本批批准。
3. **按批准批次创建。** 获准执行者在具备用户授权依据、具体批准和工具后实际创建，交接携带授权/批准来源、原 `project_key`、root/supervisor ID、上游卡、新卡和成果。新对话仍为 `executor`，不变根主控、不建监督链。
4. **统一登记与验收。** 创建者收集真实 ID/host 和配置证据，根主控统一登记创建者、上游卡、批准依据与执行清单，并维护总计划和依赖。创建者只承担卡内实现或集成；开串不增加发信或项目级协调权限。所有结果仍由原监督验收。
5. **再次扩展仍回原根主控。** 本批批准不自动转授下级；每次扩展都需新的具体批准。获准执行者缺创建/配置能力时，根主控可在同一批准范围代建并登记实际创建者，无须重复请求同一用户授权。

## 自动监督协作约定

- **归属与登记。** 根主控维护 `MASTER_PLAN.md`；监督维护 `SUPERVISION.md`（无文件工具则为可读取报告），只读被验收实现；执行者按卡拥有实现文件。委派携带角色、项目、主控/监督 ID、卡、授权和报告位置。监督者不创建执行或监督链。
- **真实且唯一。** 记录 `project_key`、`root_thread_id`、`supervisor_thread_id`、各自 `hostId`、角色、请求模型/强度、实际运行证据和执行清单（ID/host/任务/配置，扩展时加创建者/上游卡/批准来源）。先查登记及真实对话，ID 来自实际回执。失联或冲突先恢复；必须替换监督时记录原因、旧状态和完整交接，标记旧串已替换，只保留一个当前监督。
- **有界协调。** 按主控流程检查点使用有界 `wait_threads`（目标 ID/host、最新游标），必要时 `read_thread` 取原始证据；无变化不忙轮询或重复播报。子对话不能主动回发时，主控读取报告并转交即可推进。阻塞报告缺口、影响、已尝试事项、恢复条件和责任方，继续不受影响部分。

## 模型选择

在已有用户授权和宿主支持范围内，按卡的难度及预算选择具体模型与推理强度。可配置示例：

| 任务 | 模型 / 强度 |
| --- | --- |
| 清晰局部任务 | gpt-6-luna / medium |
| 原生页面与应用操作 | gpt-6.1-terra / medium |
| 常规跨文件实现 | gpt-6.1-sol / high |
| 复杂架构或关键独立验收 | gpt-6-astra / high |

创建前核对实际可用配置；记录请求值和回执，独立读取运行配置后才称已核实。无法指定或核实时说明缺口，不以默认运行冒称按卡切换，也不将最高强度视为正确性保证。
