# 独立监督与验收

## 入口与角色

大任务与 [project-master-control](../project-master-control/SKILL.md) 联动，按其分流及开工流程建立或复用唯一监督。继续、追问和修复沿用原目标与登记，不另起监督链。用户明确要求的局部核查按必要范围直接检查，不强制开串或加载大任务流程。

主控维护计划、分派和协调；执行者实施并自测；监督负责目标对齐、证据核验和问题复验。监督只读被验收实现，不替执行者修复后自行独立验收，也不创建执行或监督对话。主控不能兼任监督后宣称独立。

安装或委派不增加授权。沿用当前用户授权，遵守宿主及项目约束；缺创建、读取、发信、等待或模型能力时说明影响并完成可做的核查，内部代理不能冒称普通独立对话。只能自查时明确自查。

## 开工与变更对齐

大任务全文读取本文件、[主控入口](../project-master-control/SKILL.md)及[完整协作规则](../project-master-control/references/master-control-rules.md)，截断补齐，记录版本/资源/状态；读取原始目标、后续纠正、授权、`MASTER_PLAN.md` 和已有 `SUPERVISION.md`。只澄清影响验收且现有材料无法确定的缺口。

核对以下内容，给出“通过”或“未通过”及证据；缺口影响执行时退回受影响计划，主控修订后由同一监督复核，通过前不实施：

- **目标与事前卡：** 初始卡、共享接口、文件归属和监督/验收卡齐备，目标、授权与验收对应；登记和模型配置有真实证据，请求值与独立核实值分开。
- **粒度：** 有独立结果、不确定性、候选边界、拆/合及停止理由。可独立推进却未拆或缺有效合并理由时不放行，卡字段齐全、多个专业角色或文件少均不能证明合理。
- **执行可行性：** 完整上下文预算包含工具输出、自测、交接及返修；容量未知有处理办法；依赖解除条件、实际并行资源、关键路径及交接成本有依据，不把估计当单次上下文必成或最快证明。
- **回报对齐：** 核对唯一回报是否漏记、重复或过期，处置是否对应当前卡/契约及实际证据；检查完成与验收状态、依赖放行、冲突隔离及下一负责人，不接受一律放行或一律阻塞。
- **变化与扩展：** 用户指出拆分不足、范围扩大、反复返工或负担上升时，主控已区分标准、证据、实现与任务边界并调整。执行者扩展开串须有原始用户授权、原根主控本批批准、新卡及预算归属；沿用原 project/root/supervisor，登记实际创建者和回执，再次扩展不自动转授。开串与发信权限分别核对。

## 核验与问题闭环

将必要要求对应到实际产物、原始记录、对象、版本及验证结果。执行者总结仅用于定位证据，不能单独作为验收依据。

- 区分计划、尝试、执行成功、结果有效和最终验收。局部测试通过、文件生成或页面打开不代表目标完成。
- 用户要求真实页面、接口、环境或端到端验证时，核对实际访问及运行证据；静态核对、模拟数据和旧截图不得冒充本轮实测。复用证据前核对来源、对象、版本、时间与适用口径。
- 结论区分事实、推断和假设，并限制在证据覆盖范围。涉及数据、费用或软件发布时，按需读取[专项证据检查](../project-master-control/references/evidence-checks.md)。
- 维护 `SUPERVISION.md`；每个问题记录 ID、影响、原始证据/版本、责任任务、修复要求、复验结果和状态。主控转交原负责人修复自测，监督对最终版本复验关闭，不通过删除必要断言、跳过关键步骤或降低标准换取通过。
- 开工、目标变化、阶段结果或失败、修复后和交付前核验。报告供主控读取；主动跨对话发信须已有用户授权。当前轮结束不承诺后台持续监督。

按对目标的影响排序问题，明确缺失实施、验证、责任方和恢复条件，推进不受阻塞部分。发现实质错误时纠正受影响结论与产物，撤回失效结论，说明已修正和剩余事项。

## 最终结论

核对用户实际使用结果、必要范围及最终版本，采用与目标和风险相称的验证。关键问题未关闭不批准全部完成；部分成果明确缺口，交回主控继续授权内修复。

报告先给本轮变化和结论，详细证据用链接定位，不重复整段历史。报告包含：结论（通过/部分完成/未完成）及验证范围、可定位的关键证据、未关闭问题及影响、责任方和下一步完成判据。全部通过时不追加无关工作。
